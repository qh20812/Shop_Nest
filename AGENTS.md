# AGENTS.md

ShopNest is a Laravel 13 + Inertia 3 + React 19 e-commerce app with four roles (admin, seller, customer, shipper). The Vietnamese README is aspirational: its UI table still lists Font Awesome (0 references), and it advertises order invoice / tracking / return actions whose controller methods don't exist. Trust `composer.json`, `package.json`, `routes/` and `bootstrap/app.php`.

## Run & verify

- `composer run dev` = PHP dev server on `http://127.0.0.1:9999` (matches `APP_URL`) + `queue:listen` + Vite. `npm run dev` starts Vite only. `composer run dev:ssr` also builds and starts Inertia SSR.
- Realtime needs a separate `php artisan reverb:start` (port 8080); `composer run dev` does not start it. `SESSION_DRIVER`, `QUEUE_CONNECTION` and `BROADCAST_CONNECTION` are all `database`/`reverb` in `.env`, so queue jobs and broadcasts silently idle without those processes.
- SSR is `enabled: true` in `config/inertia.php`, but `npm run dev`/`npm run build` do not build `resources/js/ssr.tsx`; with no bundle/server Inertia just falls back to client rendering.
- Tests: `php artisan test` (or `composer test`, which runs `config:clear` first). Single test: `php artisan test tests/Feature/Seller/ProductControllerTest.php --filter=test_name`. Dusk lives in `tests/Browser` (not in `phpunit.xml`): `php artisan dusk`.
- Local PHP is 8.5: every test prints a `PDO::MYSQL_ATTR_SSL_CA` DEPRECATION from `config/database.php`. Noise, not a failure. CI uses PHP 8.4.
- PHP formatting `vendor/bin/pint`; `npm run format` (Prettier **write**, `resources/` only), `npm run format:check`, `npm run types` (`tsc --noEmit`), `npm run lint` (ESLint **with `--fix`**, not a check).
- `npm run check:css` (alias `check:tokens`) is a ratchet over `scripts/token-allowlist.json` — 112 legacy files after Phase 4. It fails on new raw hex / Tailwind utilities / legacy icon classes in TSX, `@apply`, or `!important` outside `utilities.css` + `base/a11y.css`; it scans both `resources/css/**` and `resources/js/**/*.css` (Phase 4 modules included). Never add entries; delete the entry when you migrate a file. `check:css:all` shows every remaining violation.
- CI (`.github/workflows/`) only runs for pushes/PRs to `develop`/`main`, so `refactor/ui-web` pushes skip it. Lint job: `npm install` → write-mode `pint` → `npm run format` → `npm run lint`. Test job: `npm ci` → `composer install` → `npm run build` → `phpunit`. CI runs neither `types` nor `check:css`; run both locally.
- Docker: `docker compose up --build -d` serves on `localhost:8080` (PHP 8.3-fpm + nginx) with a MySQL service on `localhost:3307`. Compose passes the repo `.env` via `env_file`, so the container still talks to the remote Aiven DB unless you override `DB_*`; the bundled MySQL is otherwise unused.

## UI state (read before touching styles)

- Two styling systems coexist on branch `refactor/ui-web`; `REFACTOR_PLAN.md` (Direction Bảng Hiệu) owns the status line and phase order — read it before restyling anything. `DESIGN.md`/`COMPONENTS.md` document the old Nếp system and are rewritten at the end of the refactor.
- **Workspace** (Seller/Admin/Shipper) is legacy: 39 files import `@/layouts/app/AppLayout`, 41 import `resources/css/Page.css` via `@/../css/Page.css`, and Boxicons classes (`bx-*`) are used ~250 times (CDN in `app.blade.php`). Do not delete `Page.css`, `base.css`, `tokens.css`, `legacy-tokens.css` or that CDN before Phase 11.
- `Page.css` is **unlayered except for six global blocks**, which Phase 3 moved into `@layer sn-legacy-reset` (`*`, `a`, `li`, `html`, `body`, `body.dark`). `sn-*` primitives now keep their padding/margin on workspace pages; the remaining `.content`, `.sidebar`, `.orders`, `.header` rules are still unlayered and win over `@layer` rules.
- `Page.css` also hard-codes the workspace geometry: 66 selectors hang off `.content` (`width: calc(100% - 230px); left: 230px`), and `.sidebar` is `fixed` with `z-index: 2000` (above `--sn-z-modal: 60`). `WorkspaceLayout` keeps `<div class="content"><main>` and uses its own `.sn-workspace__sidebar` (230 px, z 51) so dialogs can still cover it. `Pagination` renders `div role="navigation"`, not `<nav>`, to avoid `.content nav` treating it as a topbar.
- **Storefront Home/Search/ProductDetail/About/Contact/Legal** are migrated to `sn-*` + CSS Modules in Phase 4; **Auth/Account/Chat and the rest of the storefront** still use Nếp: Tailwind classes over the `@theme` in `tokens.css` (`bg-rice-paper`, `text-ink`, `text-headline-3`). New UI must use `--sn-*` tokens + `sn-*` primitives instead, and no new Tailwind classes.
- `app.css` is the only CSS entry. It imports `legacy-tokens.css`, `tokens.css`, `tokens/*` (the `--sn-*` source), `fonts.css` (self-hosted Be Vietnam Pro), legacy `base.css`, `base/*`, `components/*`, `layouts/*` and `utilities.css` (all inside `@layer sn-*`). `base/*` element rules are scoped to `.sn-shell` (body/a/label only); `StorefrontLayout` pins the shell light via `pinLight` (default `true`) until Phase 4/6, and Phase 4 pages pass `pinLight={false}`.
- Layer order is the single `@layer …` line in `app.css`; `sn-components` must stay after Tailwind `base`/`components` and before `utilities`, otherwise preflight strips input/button styling (already happened once in Phase 2A).
- Dark mode: the inline script in `app.blade.php` sets `data-theme` plus a legacy `.dark` mirror before paint; semantic tokens key on `[data-theme='dark']` and `.dark` is only for legacy CSS. `useTheme` (`@/hooks/useTheme`) mirrors all three and is SSR-safe; preference lives in `localStorage.theme`.
- `components/ui` has 47 files. Migrated primitives are plain `sn-*` classes composed with `cx` (`@/lib/cx`); `cn` (`@/lib/utils`, tailwind-merge) is still the norm in unmigrated code. Legacy files still on the allowlist: `action-button`, `action-buttons`, `action-dropdown`, `data-table`, `navbar`, `sidebar`. `table.tsx` is the new primitive, `data-table.tsx` is workspace legacy; `status-badge.tsx` is a `Badge` wrapper; `Contexts/ToastContext.tsx` is a shim — import toasts from `@/components/ui/toaster`.
- Intentionally unused, keep: `ui/{table,switch,error-state}.tsx`, `commerce/{ReturnItemPicker,RefundOption,PreferenceRow}.tsx`, `feedback/LoadingOverlay.tsx` (`switch` is only reached through the unused `PreferenceRow`).
- `ChatDock` is mounted once inside `StorefrontLayout` (`showChatDock`; `AccountLayout` wraps it). Never mount a second bubble or chatbot.
- `components/ui` file names are all lowercase in git as of Phase 3 (`avatar`, `header`, `insights`, `navbar`, `pagination`, `sidebar`, `tooltip`); keep new component files kebab-case so a Linux checkout matches the imports.

## Architecture

- Role routes: `routes/{admin,user,seller,shipper,chat,settings,auth}.php`, registered from `bootstrap/app.php` (`then:` groups); `web.php` also requires `auth`, `settings`, `admin`, `user`, `chat` and (inside its auth group) `seller`. Add role routes to the matching file. `routes/api.php` is deliberately empty — chatbot and notification endpoints sit in `web.php` under session auth (`/chatbot/message`, `/api/notifications/*`).
- Pages resolve as `Inertia::render('Seller/Products/Index')` → `resources/js/pages/Seller/Products/Index.tsx` via `import.meta.glob`; match on-disk casing exactly (`pages/` lowercase, subfolders PascalCase). 17 render targets have no page file (`Admin/CustomerSegments/*`, `Admin/Inventory/Report`, `Admin/Orders/Show`, `Admin/Returns/Show`, `Seller/Promotions/Edit|Show`, `Seller/Reports/*`, `Seller/Wallet/*`, `Product/Index|Show`, `Auth/ConfirmPassword`) and fail only at request time — known backlog, not a regression.
- 6 routes in `user.php` point at methods that do not exist on `User\OrderController` (`downloadInvoice`, `trackDelivery`, `requestReturn`, `cancelReturnRequest`, `confirmDelivery`, `createReview`), so they 500 despite being advertised in the README. Registered routes are not a reliable inventory of working features.
- Layouts are imported per page; there is no role→layout middleware. `resources/js/layouts/app/AppLayout.tsx` is a re-export of `components/layout/WorkspaceLayout.tsx` until Phase 11; the storefront/auth/account shells live in `components/layout/`.
- Naming: `components/<domain>` lowercase, component files PascalCase, `components/ui/**` kebab-case, pages PascalCase; `@` → `resources/js` (lowercase only — `@/Components/...` works on Windows but breaks tsc and Linux builds).
- Wayfinder generates `resources/js/{actions,routes,wayfinder}` (gitignored) during vite dev/build; regenerate with `php artisan wayfinder:generate`. Never edit generated files.
- Auth is session-based; Google login uses Socialite. Roles live in the `role_user` pivot with spatie-translatable names: query `Role::where('name->en', 'Seller')`, never `where('name', …)`. `$user->role_name` exists.
- Middleware aliases: `is_admin`, `isSeller`, `isShipper`, `verified`/`verified.optional` (both `EnsureEmailIsVerifiedIfProvided`; users without email count as verified). `routes/shipper.php` still uses the unregistered `shipper` alias, so its only route (`/shipper/dashboard`) 500s.
- CSRF exceptions live in `bootstrap/app.php`: `login`, `product/*/buy-now`, `buy-now/checkout/*`, `webhooks/*`. Webhooks verify signatures themselves — don't widen the list for normal forms.
- Locale switching is a POST to `/language` storing `session('locale')` (default `APP_LOCALE=vi`); currency switching is a POST to `/currency`. There are no `/{locale}/…` URL prefixes.
- Custom primary keys: `product_id`, `category_id`, `brand_id`, `variant_id`. Product/Category/Brand `name` (and product `description`) are spatie-translatable JSON (`{en, vi}`) — query with `name->en` and resolve per locale.
- Stock changes go through `App\Services\InventoryService` (`adjustStock`, `setStock`, `bulkAdjust`, `adjustInventoryForOrder`) so `InventoryLog` and caches stay consistent; never write `stock_quantity` directly.
- Payments: `App\Services\PaymentService::make($provider)` supports only `stripe` and `cod` (`app/Payments/Gateways/`); webhook/return handling is in `PaymentWebhookController`/`PaymentReturnController`.
- i18n: flat English keys in `lang/vi.json` + `lang/en.json`, shared as the `translations` prop. Use `useTranslation()` from `@/lib/i18n` (react-i18next is unused). A missing key renders the key itself, so `auth.logout` shows up as literal text today; both files also contain duplicate keys (`JSON.parse` keeps the last). Add and repair keys in **both** files.

## Data & tests

- `.env` points at a shared remote MySQL (Aiven), not localhost: treat `migrate:fresh`, `db:wipe` and seeders as destructive and ask first. Tests use SQLite `:memory:` via `phpunit.xml`.
- Feature tests use `RefreshDatabase`. Seed roles first (`$this->seed(RoleSeeder::class)`), then `$user->roles()->attach(Role::where('name->en', 'Seller')->first())`; assert with `Inertia\Testing\AssertableInertia`. `config/inertia.php` has `ensure_pages_exist: false` (only `testing` flips it to `true`), so a missing page fails at request time rather than at build.
- Chatbot tests `Http::fake` `api.openai.com` (and Groq); fake any new provider. Test env pins `APP_LOCALE=vi`, `QUEUE_CONNECTION=sync`, `BROADCAST_CONNECTION=log`.

## Deps

- Laravel 13, Inertia 3, React 19, Vite 8, Tailwind 4, TypeScript 5.9, recharts 3, lucide-react 1.x. Locks are in sync; run `npm ci` after switching branches instead of trusting `node_modules`.
- `tailwind.config.ts` is not loaded (Tailwind v4 is CSS-first): add tokens under `resources/css/tokens/`, not the JS config. shadcn-style `components.json` is vestigial. `@fortawesome/fontawesome-free` is an unused dependency slated for Phase 11 removal.
